Eco⁠-⁠Sentry

Anti‑poaching acoustic detection for Indian forest reserves. Listens for gunshots, chainsaws and vehicles, classifies them on a spiking neural network, encrypts the detection into a sub‑1 KB alert, and delivers it to a command centre over a simulated LoRa mesh — while a power model tracks whether the solar‑charged edge node survives a 30‑day deployment.

What doesn't work yet

Written up rather than hidden — the point of a field report.
47.5%

False-alert rate on pure-ambient audio. Of 40 forest-background clips with no threat present, 19 crossed the alert threshold. This is a design gap, not a bug: the trained head is a 3-class softmax over gunshot / chainsaw / vehicle, with no “none of these” option — a real device listens to ambient forest ~99.99% of the time, so this metric would dominate field performance. The fix (train a 4-class head including the ambient class already carried through ARCH_1–3) is the smallest change and is deliberately left undone rather than silently changing the specified architecture.

Corrections made to the design documents

01LIF neurons could never fire
With V ← αV + (1−α)I, α = e⁻¹ and I ∈ [0, 1], the membrane asymptote equals I, so it can never cross v_th = 1.0 — firing rate collapses to 0%, not the required 25%. Fixed with an explicit input gain, auto-calibrated per corpus by binary search. Typical gain 1.7–2.7.
02Firing-rate normalisation was a no-op
ARCH_3 multiplies a binary tensor by target/current and clips to [0, 1]; for any factor > 1 that returns the input unchanged. Fixed by adjusting the spike count directly — dropping the least salient spikes when too dense, recruiting the strongest sub-threshold candidates when too sparse.
03Xavier init left the network dead
With v_th = 1.0, the documented Xavier initialisation gives hidden-layer firing rates of 0.19% and 0.0% — zero surrogate gradient, training collapses to a constant prediction. Fixed with an LSUV-style rescale so each hidden layer starts at ~20% firing.
04LoRa time-on-air figures are ~4× too low
The spec quotes 56ms at SF7 and 1.5s at SF12 for a 116-byte payload. The SX1276 datasheet formula gives 220ms and 5.1s. Consequence: SF12 alone cannot meet the 1.5s latency target — the simulator uses adaptive spreading factor, which is what keeps p99 latency under 600ms.
05AES mode conflict — CBC chosen over ECB
The spec's component table says CBC with a random IV; its cross-reference table says ECB. ECB leaks equality between identical plaintexts, letting an eavesdropper fingerprint repeated alerts. CBC costs 16 extra bytes and closes that leak.
06The 50–75× power-reduction target is unreachable by construction
It assumes 0.5mW quiescent power, which the spec's own corrections table supersedes with 50mW. At 50mW the ceiling is 600/(50+3) ≈ 11×. This implementation reports 12× system average / 18× compute path and marks the criterion FAILED with this explanation, rather than quietly reporting a number that flatters the design.

Not implemented

  • Firmware for the Cortex-M4/M7 target — inference path is pure NumPy; INT8 quantisation exists, no C export
  • Real MQTT client — gateway records publishes in memory, swap for paho-mqtt at the same interface
  • Command-centre dashboard and ranger-facing app
  • Over-the-air key rotation — only key generation and PBKDF2 derivation are implemented
